## Important fixes in V14.2

### P0 — historical feature clock separation

A pre-match record's `available_at` is not the same clock as the eventual result/statistics availability. V14.2 therefore requires an explicit `outcome_available_at`, `result_available_at` or `stats_available_at` field before a completed match can be inserted into historical team state. The implementation never invents this timestamp.

### P0 — validation/test contamination risk

The previous research pipeline evaluated every candidate directly on each test window. That can turn the test window into a model-selection surface. V14.2 selects the champion using validation log loss only, optionally calibrates using validation predictions only, then evaluates the selected champion once on test.

### P0 — same-timestamp temporal overlap

Timestamp predicates can duplicate events when several matches share the same event time. V14.2 records row-index boundaries in each walk-forward fold and uses those boundaries for train/validation/test slicing, with an explicit event-overlap assertion.

## External acquisition blockers

The project runtime used for this build had no usable outbound network access. Paid historical providers also require the appropriate credentials/subscription. The correct behavior is therefore to leave the acquisition pipeline ready rather than fabricate or substitute current odds for historical snapshots.

## Source architecture

Current recommended architecture:

1. Football-Data.co.uk — broad historical results/stats/opening/closing-price complement; not exact timestamp PIT by itself.
2. The Odds API — primary candidate for timestamped bookmaker historical snapshots where coverage/plan supports the target sport/market.
3. TheStatsAPI — sports/statistics/xG/odds candidate; requires a real POC to confirm the exact timestamp semantics available under the subscribed plan.
4. Betfair Historical Data — independent timestamped exchange validation / market microstructure source.
5. StatsBomb Open Data — event/lineup feature complement for supported competitions; not an odds source.
6. Flashscore — optional complementary source only when access is legitimate and technically supported; no aggressive scraping or protection bypass is part of this project.
