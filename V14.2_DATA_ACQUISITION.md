# V14.2 REAL DATA ACQUISITION RUNBOOK

## Required environment variables

```text
THE_ODDS_API_KEY=<paid historical API key>
THESTATSAPI_KEY=<provider key if used>
HISTORICAL_DATA_PATH=<validated local dataset>
```

## Acquisition order

1. Acquire a real historical match/statistics source.
2. Acquire timestamped historical odds snapshots for the same event universe.
3. Preserve raw provider payloads unchanged.
4. Normalize into canonical event/team/competition/bookmaker/market/selection entities.
5. Resolve entities with a confidence-bearing mapping table.
6. Validate timestamps before feature construction.
7. Build the PIT dataset manifest and hashes.
8. Reject the dataset if any strict PIT gate fails.
9. Only then execute temporal training, calibration, backtest and OOS.

## Important rule

Do not replace historical snapshots with current odds. Do not convert an opening-price field into an exact publication timestamp. Do not invent ingestion/source timestamps.

## Football-Data command

```bash
python ml/scripts/acquire_football_data.py --season 2425 --league E0
```

The adapter intentionally marks its odds as non-exact PIT when the source does not provide an exact availability timestamp.

## The Odds API

Use the historical endpoint through `ml/app/adapters/odds.py`. Preserve the provider's snapshot timestamp and request the snapshot at or before the target decision time.

## TheStatsAPI

Use `ml/app/adapters/the_stats_api.py`. Provider-plan-specific response fields must be mapped to the canonical schema. Exact PIT status is granted only after timestamp evidence passes the strict validation gate.

## Betfair

Use `ml/app/adapters/betfair.py` for purchased local extracts. The adapter does not download or fabricate provider data.
