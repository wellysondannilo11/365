# ROBO DA BET — V14.2 SOURCE COMPARISON

| Source | Results/Stats | xG/Events | Historical odds | Exact timestamp PIT | Bookmakers | Cost/access | Role |
|---|---|---|---|---|---|---|---|
| Football-Data.co.uk | Strong | Match stats | Opening/pre-closing/closing sets | No exact odds-publication timestamp in CSV | Multiple | Public/free files | Historical backbone + cross-check |
| The Odds API | Events | Limited sport-data role | Historical snapshots | Strong candidate; snapshot timestamp available | Multiple supported books | Historical access requires paid plan/API key | Primary bookmaker PIT candidate |
| TheStatsAPI | Strong | xG/events/players depending plan | Historical/opening/last-seen odds advertised | Must be verified in POC for exact PIT semantics | Multiple | Paid/trial access depending plan | Sports/statistics + odds complement |
| Betfair Historical Data | Exchange events | Market data | Exchange historical prices | Timestamped | Betfair Exchange | Purchased/downloaded data | Independent market validation |
| StatsBomb Open Data | Matches/events/lineups | Strong event data | No bookmaker odds | Event timestamps are not odds-availability timestamps | N/A | Public selected competitions | Feature complement |
| Flashscore | Strong UI-level coverage | xG/stats/events | Not selected as PIT source | Not established for this architecture | N/A | Access constrained by provider terms | Optional complement only |

## Decision

Use a multi-source architecture rather than forcing one provider to supply every layer.

**PIT odds:** The Odds API is the primary candidate.

**Historical football/statistics:** Football-Data.co.uk plus TheStatsAPI/StatsBomb where their coverage and licensing fit the target dataset.

**Independent market validation:** Betfair Historical Data.

**Flashscore:** not foundational; no scraping bypass or CAPTCHA/rate-limit circumvention.

## Critical acceptance rule

A source is not considered exact-PIT merely because it advertises "opening odds" or "historical odds". The dataset must expose a defensible availability/source timestamp that satisfies:

`available_at <= decision_time`

If that evidence is absent, the record remains bounded/non-exact and cannot be silently promoted to strict PIT.
